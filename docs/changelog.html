v0.7.02026-11-27Release notes

  • A switch no longer signals waybar itself (SIGRTMIN+12): that number can be another module's signal there (it refreshed Vayu's jyoti capsule on every switch). Only a running vesha waybar stream is told to redraw; a bar using --once follows --sources.
  • vesha waybar --sources prints the files the bar line comes from (the accounts, the usage cache, the config), so a bar that already watches files can run vesha waybar --once when one changes instead of keeping vesha waybar running (about 18 MB less on a desktop that only wants the line on a change). The line is the same; a usage window resetting shows at the usage cache's next write instead of within a minute.
  • vesha waybar --once (and the claude wrapper) start faster: the network code is loaded only when usage is actually fetched, so an answer from the cache takes about 70 ms of CPU instead of 170.
  • The website, closer to Vayu's own: the tool's screenshot blurred behind the page, a centred hero with the logo and the verse, the page you're on as the white pill, glass "On this page" and footer panels, releases as cards. No glow behind the logo, no coloured line beside the verse.
  • The website has Vayu's Spatial look: graphite glass, a floating navigation bar, near-white for links and the main button, and the tool's own colour only as its signature (the logo's glow, the shloka's line, the release dots). No more all-caps labels.

v0.6.02026-11-16Release notes

  • With every account at its limit, the watcher now switches to the one whose limit resets first (it used to stay on the active one and only say when the first resets). An account frees up only when every full window has reset, so a full week isn't hidden by a 5-hour window resetting soon. Paused accounts, and ones whose reset time or usage is unknown, are never picked; it switches only for a reset at least a minute sooner, so two accounts resetting together don't swap back and forth. One notification says it all, and the watcher looks again right as the reset happens. With auto off it names the account that frees up first. ADR 12.
  • vesha waybar --once prints the current line and exits, for a bar that starts after vesha (tmux after a reboot) and would otherwise wait for the next change.
  • vesha waybar shows usage as it is now: a window that has reset reads 0%, not its last 100%; the colour follows the fuller of the 5-hour and weekly windows, and a nearly full week is shown as week N%.

v0.5.02026-11-09Release notes

  • Fixed: automatic switching stopped working when Claude Code's usage endpoint answered 429 ("asked too often"). vesha then had only the active account's last known numbers, and the watcher ignored those, so an account at 100% stayed active. Old numbers now count: usage only grows inside a window, so a last known 100% that hasn't reset is still true.
  • Live usage from Claude Code itself: vesha service install points the status line at vesha feed, which takes the 5-hour and weekly limits Claude got with each reply, keeps them as that account's usage, and wakes the watcher at once near a limit. An existing status line keeps showing; vesha service remove puts it back. Right after a switch, a session's numbers from the old login are told apart and ignored.
  • Far fewer requests: the watcher asks the endpoint only for numbers older than a minute (when close) or three, and other accounts' only near a limit and at most every ten minutes; the bar reuses them. After a 429 an account isn't asked again for 1, 2, 4 ... up to 15 minutes.
  • Switches at 95% (was 98%), so the reply that crosses the line doesn't hit the wall first. A window whose reset time has passed counts as empty when choosing where to go; fresh numbers win a tie.
  • The usage cache is locked and merged, newest first, so the watcher, the bar, the switcher and every status line can write it at once.
  • vesha switch with no name, and scrolling on the bar, skip paused accounts, as automatic switching always has; naming one still goes there.
  • vesha doctor checks the status line feed; a switch that fails (Claude renewing the login) is tried again after 20 seconds, not two minutes.

v0.4.02026-11-09Release notes

  • The switcher speaks the Space grammar every Vayu tool shares: normal and insert modes, Space as the leader with a which-key strip after 0.3 s, a Space Space palette of every action, ? built from the same key table. The keys are data in vesha/tui.py (BINDS), run through Vyom's keys module (vendored as vesha/keys.py by Vyom's scripts/vendor-keys.sh); scripts/keybinds.py writes the # keybind: lines from it and CI checks them.
  • Moved keys: running claude is o (was r); r refreshes usage (was u, which now says where it went); tabs are H / L (h, l, Tab still work); copying the email is yy; adding an account is Space a a (a still works); renaming is cw (R still works).
  • A number alone no longer jumps to an account after 0.6 s: it's a count (3j, 3G, 3gg), so switching tabs and moving never wait.
  • Removing asks and only y says yes (Enter used to say yes too).
  • The sign-in code field opens in insert mode; Esc goes to normal mode and Esc again cancels, so a stray Esc doesn't throw the sign-in away.
  • Fixed: F1, Insert and other keys with no character typed a stray letter into the search, rename and sign-in fields (and a typed "ă" could act as Up). CI's "every switcher key is in the README" check matched no lines after the annotations gained :normal, so it passed without checking.

v0.3.02026-10-21Release notes

  • Switching reaches running sessions: the active account's login now lives in ~/.claude, and a switch (vesha switch, the switcher, or the watcher at the limit) moves the target's login there and the old one to its profile. Every claude uses the new account from its next message, the session that hit the limit included, like claude-swap but without copying a login (ADR 9). A switch waits while Claude renews the active login, is refused while a session runs inside the target's own profile (--force overrides), and keeps a renewal that lands mid-swap.
  • Reset times are a day and a time: "today 9:40 PM", "tomorrow 6:00 AM", "Sat 6:00 AM" (a date further out), in the switcher, vesha usage, vesha list, waybar's tooltip and the watcher's notifications, instead of "in 4h 12m".

v0.2.32026-10-21Release notes

  • Usage bars are thin lines now: the used part a bold line in green, yellow or red, flowing into a faint hairline for the rest, to half a cell. No background colour, so they suit a transparent terminal and rows no longer run together (v0.2.2's solid pills looked heavy).

v0.2.22026-10-21Release notes

  • Better-looking usage bars, in the switcher and the CLI: rounded pills on a soft track, filled to an eighth of a cell, wider in the overview.
  • Their colour follows what's used: green while there's plenty left, yellow from half, red from the warning level (warn_at, 85%). Plain [####----] bars without colour.

v0.2.12026-10-21Release notes

  • vesha import cswap restores a lost login: an account vesha has but that lost its login (e.g. after vesha repair) is signed back in from claude-swap's saved copy.
  • h / l go to the accounts / folder rules tab (arrows too), and Tab reaches the folder rules tab even when there are none yet.
  • Rounded capsules for the tabs, tags, mode and key hints, like the tmux bar.
  • Every switcher key is exercised end to end against a throwaway home.

v0.2.02026-10-21Release notes

  • Sign in without leaving vesha: a in the switcher asks for a name and an email, opens Anthropic's sign-in page in your browser with the email filled in, and adds the account when you've entered the emailed code there; if the page shows a code, paste it into vesha. Ctrl+o reopens the page, Ctrl+y copies the link, Esc cancels and cleans up. vesha add <name> <email> does the same from a shell; vesha login fills in the account's email.
  • A new look, like sangam: a tab strip (accounts, folder rules, the account a new claude uses here, auto-switching, ? keys), the accounts in a rounded pane with column headers and a marker on the selected row, and an overview pane with usage, login, profile, folders and "what now". Stacks into one column on narrow terminals.
  • Fixed: the last column of the screen was never drawn; doctor no longer checks shared files of a profile that isn't made yet.

v0.1.32026-10-21Release notes

  • vesha repair: when another tool replaced a profile's login (e.g. claude-swap wrote another account into ~/.claude), two accounts showed the same usage under the wrong email. repair makes the records match the logins, moves the duplicate profile to vesha's trash folder, forgets the numbers cached under the wrong name, and says which account to sign in again. It shows the plan and asks first.
  • The switcher flags it: a red "login changed" tag and a line saying who is really signed in; vesha doctor points to vesha repair.
  • vesha login <name> tells you which account to pick, and refuses one that is already another account's.

v0.1.22026-10-21Release notes

  • Catches logins changed behind vesha's back: vesha doctor says when a profile is now signed in to a different account than the one added (e.g. claude-swap or a /login changed ~/.claude), and when two profiles hold a copy of the same login.
  • Never renews a copied login: renewing one copy logs the other out (a running session, possibly), so vesha leaves it to Claude Code and says so.

v0.1.12026-10-21Release notes

  • Accounts and profiles moved to ~/.local/state/vesha: v0.1.0 kept them in ~/.local/share/vesha, where kosha and install.sh put vesha itself. They're moved on first run (not while a session runs on an old profile); installing or removing vesha never touches a login (ADR 8).
  • vesha service status shows the watcher's last log lines.
  • vesha list with no accounts yet is not an error (exit 0); doctor checks this home's watcher unit, not just systemd.
  • The switch note is accurate about folder rules and running sessions.

v0.1.02026-10-21Release notes

The first release: every Claude Code account signed in at once, one key to switch, and automatic switching when the active one hits its limit.

  • Profiles, not swaps: each account is its own Claude Code profile (CLAUDE_CONFIG_DIR); the account in ~/.claude stays where it is. Switching never touches a login, and running sessions keep their account.
  • Switch from anywhere: vesha switch [name] changes the account every new claude uses, in every folder and terminal, through a small claude wrapper (vesha install-shim). vesha use for one terminal, vesha run for one command, optional folder rules with vesha map.
  • Automatic switching: vesha service install runs a watcher that warns at 85% of either limit (with a "Switch to …" button) and switches at 98% to the account with the most room, skipping paused and full ones. Each warning is shown once per limit window, even across restarts.
  • The switcher (vesha): every account with its plan, 5-hour and weekly usage and reset times, tags for active / here / paused / running sessions, and the folder rules. Vim keys: j/k, gg/G, Ctrl+d/Ctrl+u, counts, 1-9, Tab, Enter, r, u, p, m, a, R/cw, dd, y, / with n/N, and ? for all of them. Adapts from 80 columns up.
  • Shared setup and history: CLAUDE.md, settings, skills, plugins, agents, commands and history are linked from ~/.claude into every profile, so claude --continue works across accounts.
  • Usage everywhere: vesha usage, vesha list and a waybar module (vesha waybar) that redraws the moment the account changes.
  • Logins stay safe: one copy of each login (Claude Code rotates them), tokens renewed in place only when Claude isn't running on that profile, files private to you, no token ever printed.
  • vesha import cswap brings claude-swap's accounts across.
  • vesha doctor, vesha init zsh|bash (shell hook and completion), --json output, help for every command, ruff, tests and a website with the changelog and design decisions.
